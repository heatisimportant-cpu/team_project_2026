# MPC – Winter 2026 Heating System

This repository contains a heating system model for the multi‑family house at Virchowstr. 6 in Langenhagen (MFH 1968, EnEV standard). The goal is to compare a normal weather‑compensated control with a price‑aware control that uses a 500 L buffer tank to shift electricity use to cheaper hours, while keeping the room temperature around 21 °C (21 ± 1 °C).

At the moment the project focuses on one period:

- **Winter 2026**: 1 December 2025 – 28 February 2026 (2137 hours)

The model uses a reduced‑order 4R3C building model, hourly weather data for the Hannover region, hourly electricity prices (Tibber‑like), a residential internal gains profile including **measured solar irradiance data** from DWD station Hannover, and a simple thermal storage tank model.

---

## 1. Quick start

```bash
# Install dependencies
pip install -r requirements.txt

# (Optional) Regenerate solar gains from the DWD irradiance CSV
python data/solar/calc_solar_gains.py

# (Optional) Run unit tests
pytest tests

# Run the Winter 2026 comparison
python examples/simulation/run_winter_2026.py
```

The script runs two cases:

1. **Baseline**: heating curve controller, no buffer tank  
2. **MPC + tank**: price‑aware controller with 500 L buffer tank and 21 ± 1 °C comfort band

All results are written to `examples/simulation/results`.

---

## 2. What the Winter 2026 simulation does

`examples/simulation/run_winter_2026.py`:

1. Loads the MFH 1968 Virchowstr. 6 building data from `data/buildings/mfh_1968.py`.
2. Loads weather, electricity prices, and gains (internal + solar) from CSV files.
3. Cuts all time series to the period 2025‑12‑01 to 2026‑02‑28.
4. Runs:
   - a **baseline** controller with a heating curve and proportional feedback,
   - an **MPC‑like** controller with a 500 L buffer tank that uses price information plus tank SOC to shift heat pump operation.
5. Computes heat delivered, electricity use, costs and comfort statistics.
6. Saves full hourly results to CSV and creates 15‑day time‑series plots (7 subplots each, including solar gains).

## 3. Controllers

### 3.1 Baseline: heating curve (no tank)

The baseline controller behaves like a typical weather‑compensated system:

- **Heating curve**: supply temperature as a function of outdoor temperature.
- **Feedback**: a proportional term around 21 °C corrects deviations.
- **Deadband**: reacts only when the room tries to leave the 21 ± 1 °C band.
- **No buffer tank**.

### 3.2 MPC + 500 L buffer tank

The MPC‑like controller adds a tank and uses the price signal:

- **Tank model**: 500 L water buffer, SOC (0–100 %), simple standing-loss term.
- **Price logic**: charge during cheap hours, discharge during expensive ones.
- **Comfort**: target 21 °C, deadband ±1 °C.

## 4. Building model (4R3C)

States: `T_room`, `T_wall`, `T_hp_ret`

Inputs:

- `T_hp_sup` – supply temperature  
- `T_amb` – outdoor temperature  
- `Q_gains` – **total gains = internal occupancy/appliances + solar gains through windows**

The parameters are derived from `data/buildings/mfh_1968.py` (MFH 1968, EnEV after 2016 refurbishment).

---

## 5. Data files

### 5.1 Building data

`data/buildings/mfh_1968.py` — floor area, H_tr, H_ve, thermal capacity, window geometry (East / South / West / North areas and orientations).

### 5.2 Weather

`data/weather/hannover_2024_2026.csv` — hourly outdoor temperatures.

### 5.3 Electricity prices

`data/prices/electricity_prices_2024.csv` — hourly prices; shifted by +1 year for the 2025/2026 period.

### 5.4 Internal gains + solar gains

`data/profiles/internal_gains.csv` — hourly gains profile with four columns:

| Column | Description |
|---|---|
| `timestamp` | Hourly UTC timestamp |
| `Q_int_specific` | Occupancy/appliance gain [W/m²] |
| `Q_sol` | Solar heat gain through windows [W] |
| `Q_int_total` | Total gains used by the model [W] |

`Q_sol` was computed from the measured DWD solar irradiance data by `data/solar/calc_solar_gains.py`.

### 5.5 Solar irradiance (new)

`data/solar/hannover_solar_2024_2026.csv` — 10-minute irradiance measurements from DWD station Hannover (station ID 2559), covering November 2024 – May 2026.

`data/solar/solar_gains_hourly.csv` — hourly solar irradiance and building window gains derived from the above, covering the full simulation range.  Generated by `data/solar/calc_solar_gains.py`.

For full details on the solar gain methodology see **DATA_GENERATION.md §5**.

## 6. Output

After a run you will find in `examples/simulation/results`:

- `winter_2026_baseline.csv`  
- `winter_2026_mpc.csv`  
- `winter_2026_days_001_015.png` … `winter_2026_days_076_090.png`

Each PNG shows a 15‑day section with **7 subplots**:

1. Room temperature (with 20–22 °C comfort band)  
2. Supply temperature  
3. Heat output  
4. COP  
5. Tank SOC (MPC only)  
6. Solar gains [kW]  
7. Outdoor temperature

The CSV files contain the full hourly time series including the `Q_sol` column.
